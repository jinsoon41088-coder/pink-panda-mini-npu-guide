📚 1. 실패 원인 분석이란 무엇일까요?

프로그램을 실행했을 때 예상했던 결과와 실제 결과가 다르게 나타날 수 있습니다.

왜 이런 결과가 나타났는지 확인하고 문제의 원인을 찾아가는 과정을 실패 원인 분석이라고 합니다.

② 실제 결과 확인하기

④ 실패 원인 조사하기
⑤ 필요한 부분 수정하기
⑥ 다시 테스트하기

실패 원인을 분석하는 것은 디버깅(Debugging)의 중요한 과정입니다.

🍌 2. 바나나 주스로 쉽게 이해하기

핑크판다가 맛있는 바나나 주스를 만들려고 합니다.

🍌 바나나 2개
🥛 우유 200ml
🥤 믹서기로 섞기

그런데 예상했던 맛과 다르게 주스가 만들어졌습니다.

📂 재료가 잘못된 경우

바나나 대신 다른 과일을 넣었다면 데이터 문제와 비슷합니다.

💻 만드는 방법이 잘못된 경우

재료는 올바르지만 믹서기를 작동하지 않았다면 로직 문제와 비슷합니다.

🔢 측정값을 비교하는 방법이 잘못된 경우

측정 도구의 작은 오차를 고려하지 않고 우유의 양이 정확히 200ml인지 판단한다면 수치 비교 문제와 비슷합니다.

📂 3. 데이터 및 스키마 문제

데이터 문제는 프로그램에 전달되는 입력값이나 데이터의 내용이 잘못된 경우입니다.

스키마는 데이터가 어떤 구조와 규칙을 따라야 하는지 정해 놓은 것입니다.

잘못된 배열 크기

❌ 필요한 배열: 5×5
실제 입력 배열: 3×3
문제: 배열 크기 불일치
✅ 해결 방법
입력 배열과 필터의 행과 열 개수를 확인하고 정해진 크기와 일치하는지 검사합니다.

잘못된 JSON 데이터

{
    "input": [
        [0, 1, 0],
        [1, 1, 1],
        [0, 1, 0]
    ]
}

위 데이터에는 예상 정답을 나타내는 expected 항목이 없습니다.

❌ 필수 항목 expected 누락

수정된 JSON 예시

{
    "input": [
        [0, 1, 0],
        [1, 1, 1],
        [0, 1, 0]
    ],
    "expected": "+"
}
✅ 필수 항목이 포함되어 있습니다.

데이터 검사에서는 배열 크기, 숫자 자료형, 필수 키, 허용된 라벨 등을 확인해야 합니다.

💻 4. 로직 문제

로직 문제는 입력 데이터가 올바르지만 프로그램의 계산 방법이나 처리 순서가 잘못된 경우입니다.

잘못된 MAC 연산

score = 0

for i in range(n):

    for j in range(n):

        score = pattern[i][j] * filter_data[i][j]
❌ score = 를 사용하면 이전에 계산한 점수가 덮어써집니다.

올바른 MAC 연산

score = 0

for i in range(n):

    for j in range(n):

        score += pattern[i][j] * filter_data[i][j]
✅ score += 를 사용하면 이전 계산 결과에 새로운 계산값을 더합니다.

🎮 잘못된 계산과 올바른 계산 비교하기

3×3 십자가 입력 패턴과 십자가 필터를 비교합니다.

0 1 0
1 1 1
0 1 0
계산 버튼을 눌러주세요.

🔢 5. 수치 비교 문제

컴퓨터는 일부 소수를 정확하게 표현하지 못할 수 있습니다.

사람이 예상한 결과
0.1 + 0.2 = 0.3

컴퓨터의 부동소수점 계산 결과
0.30000000000000004

정확히 같은지 비교하는 방법

0.1 + 0.2 == 0.3

# False

허용오차를 이용하는 방법

epsilon = 1e-9

abs((0.1 + 0.2) - 0.3) < epsilon

# True
비교 버튼을 눌러주세요.

Mini NPU에서는 두 필터의 점수 차이가 epsilon보다 작으면 UNDECIDED로 판정합니다.

UNDECIDED가 나왔다고 해서 반드시 프로그램의 오류인 것은 아닙니다.

정해진 판정 규칙을 올바르게 적용했는지 먼저 확인해야 합니다.

📋 6. PASS와 FAIL의 차이

예상 정답 실제 판정 테스트 결과
Cross Cross PASS
X X PASS
Cross X FAIL
X UNDECIDED FAIL
Cross UNDECIDED FAIL

PASS는 예상 정답과 실제 판정이 일치했다는 의미입니다.

FAIL은 예상 정답과 실제 판정이 일치하지 않았다는 의미입니다.

FAIL이라는 결과만으로는 실패의 정확한 원인을 알 수 없습니다.

🧪 7. PASS와 FAIL 직접 체험하기

예상 정답과 실제 판정을 선택해 주세요.

🔍 8. 실제 미션 실패 사례 분석

이전 Mini NPU 실습에서 기록된 실패 사례를 살펴봅시다.

테스트 이름 예상 정답 실제 판정 결과
size_5_1 X UNDECIDED FAIL
size_13_2 Cross UNDECIDED FAIL
size_25_1 X UNDECIDED FAIL
⚠️ 위 사례는 실제 판정과 예상 정답이 일치하지 않았던 기록입니다.

정확한 실패 원인은 아직 확인되지 않았습니다. 따라서 데이터 문제, 로직 문제, 수치 비교 문제 중 어느 하나라고 단정할 수 없습니다.

실패 원인을 조사하는 순서

① 테스트 이름 확인
② 배열 크기 확인
③ JSON 필수 항목 확인
④ 예상 정답 라벨 확인
⑤ 입력과 필터 데이터 확인
⑥ MAC 연산 코드 확인
⑦ Cross 점수 확인
⑧ X 점수 확인
⑨ 두 점수의 차이 확인
⑩ epsilon 판정 규칙 확인
⑪ 원인 수정 후 재테스트

테스트를 통과시키기 위해 근거 없이 예상 정답이나 epsilon 값을 변경하면 안 됩니다.

🎯 11. 동료평가 예상 질문과 답변

Q1. 실패 원인 분석이란 무엇인가요?

A. 예상 결과와 실제 결과가 다른 이유를 조사하고 해결 방법을 찾는 과정입니다.

Q2. 실패 원인은 어떻게 분류하나요?

A. 데이터 및 스키마 문제, 로직 문제, 수치 비교 문제로 나누어 조사할 수 있습니다.

Q3. 데이터 및 스키마 문제의 예시는?

A. 배열 크기가 다르거나 JSON의 필수 항목이 누락된 경우입니다.

Q4. 로직 문제의 예시는?

A. MAC 연산에서 score += 대신 score = 를 사용하여 이전 점수를 덮어쓰는 경우입니다.

Q5. 수치 비교 문제의 예시는?

A. 부동소수점 오차를 고려하지 않고 두 실수가 정확히 같은지 비교하는 경우입니다.

Q6. UNDECIDED는 무조건 오류인가요?

A. 아닙니다. 두 점수의 차이가 epsilon보다 작다면 정상적인 판정 결과일 수 있습니다.

Q7. FAIL이 나오면 무엇부터 확인하나요?

A. 예상 정답과 실제 판정을 비교하고 입력 데이터와 계산 점수, 판정 규칙을 순서대로 확인합니다.

Q8. 실패 리포트에는 무엇을 기록하나요?

A. 테스트 이름, 예상 정답, 실제 판정, 실패 원인, 확인한 근거와 해결 방법을 기록합니다.

Q9. 실패 원인을 찾지 못했다면?

A. 확인되지 않은 원인을 단정하지 않고 조사 중이라고 기록한 뒤 필요한 데이터를 추가로 확인합니다.

Q10. 오류를 수정한 후에는 무엇을 하나요?

A. 같은 테스트를 다시 실행하고 다른 테스트에도 문제가 발생하지 않았는지 확인합니다.
